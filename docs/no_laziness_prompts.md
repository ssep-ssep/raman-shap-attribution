# 防偷懒提示词模板库

> 适用场景：vibe coding、长时间多步骤任务，模型刚做出修复/规划就停下回合时使用。
> 使用方式：直接把对应模板粘到下一轮对话开头（或作为系统提示词片段）。

---

## TL;DR — 一句话应急

> 用 todo_write 先把所有剩余步骤写下来，逐条标 in_progress 并完成后再回复我；不允许只给文字说明就结束回合。

---

## 模板 A：通用多步骤任务

适用：任何「把 X 改完/跑通/交付」类任务。

```
任务：[一句话目标 + 验收标准]

执行约束（重要，必须遵守）：
1. 收到任务后立刻调用 todo_write，把所有可识别的子步骤一次性列出来。
2. 每完成一个步骤立刻把对应 todo 标 completed，然后立刻开始下一项。
3. 在所有 todo 都标 completed 之前，你的回合不能以纯文本结束；
   任何包含 "我来…/我用…/接下来…/修：/方案：" 但没有 tool call 的回复都视为偷懒。
4. 如果中途需要我确认，提供一个最小化的问题（ask_user_question），但确认后必须继续执行，不要等下一轮。
5. 整个任务没有交付（文件已写 + 验证完成 + 简明总结）之前不要停止。
```

## 模板 B：图像/可视化调优（Vibe Coding 专用）

适用：matplotlib / plotly / echarts 等出图，每轮只能看到一张图。

```
目标：让 [图名] 在视觉上 [具体标准，如：刻度无重复、图例不与数据重叠、坐标不重叠]。

执行约束：
1. 第一步：todo_write 列出所有已知问题（重复 x-tick、图例压线、字号…）。
2. 每轮必须按以下循环，直到所有 todo 标 completed：
   a. 用 edit 修改代码
   b. 用 pwsh 跑一次脚本
   c. 用 read_image 看最新结果图
   d. 对比验收标准，若不通过：回到 a；若通过：标 completed，进入下一条
3. 任何一轮如果「读图 + 改代码 + 重跑」只做了其中部分（特别是只承诺不改），
   视为偷懒，必须在同一轮补齐后续步骤。
4. 全部完成后用一句话列出「修了什么 + 还存在什么」。
```

## 模板 C：后台子代理/工具调用频繁中断

适用：模型声称要派 subagent / 后台跑，但只发了一个 setup 调用就停。

```
执行约束：
1. 用 subagent 时必须 run_in_background=true 并立即继续做能并行的事。
2. 当你回复里出现「我让子代理…/我跑后台…」这种宣告，
   后续回合必须包含真实的工具调用（job_output / send_message / read），
   否则视为空承诺回合。
3. 子代理回来的结果必须立即整合（不是又开新回合说"我接着干"）。
```

## 模板 D：长上下文 + 多次 read_image 后变迟钝

适用：粘贴图后模型进入「描述现状」模式不肯动手。

```
你现在倾向于只描述图像问题而不修改代码。
立即停止描述，改为：edit 一处最可能解决的代码行 -> pwsh 跑 -> read_image 验证。
最多再做 3 轮这样的循环；如果仍未达标，再回来问我要不要换方案。
```

---

## 判定「空承诺回合」的客观信号

粘贴到任意复盘判断里：

- 该回合**没有 tool call**，但文本以 `:` `；` `修：` `方案：` `我来…` 结尾
- 该回合**总 token < 50**，且没有任何 read/edit/pwsh 调用
- 同一任务**已出现 2 次以上**「我接着干 / 继续」类的描述
- `todo_write` 存在 in_progress / pending 项时，模型却以纯文本收尾

满足任一即可判定为偷懒，应触发模板 A 重新约束。

---

## 模板 E：换 agent 接力

适用：当前模型已经持续偷懒，硬约束也无效时。

```
现在你明显在做空承诺回合。我换一种约束方式：
不要给我"计划"，直接开始动手。
第一步：先 edit 当前文件最可能解决 [具体问题] 的那一行；
如果改了不对，我下一条消息会指正，你再改；不要在第一轮就描述"接下来会怎么做"。
```

---

## 使用建议

1. **优先用模板 A + todo_write**——90% 的偷懒场景下，强制列 todo 就够了。
2. **图像/可视化任务用模板 B**——三步循环（改→跑→看图）天然防止单步停。
3. **多 agent 协作时叠用模板 C**。
4. **实在不行，模板 E 直接堵嘴**。
5. 终极方案：用 DSH 的 `create_goal` 跨回合续轮，让偷懒回合根本不会发生。
